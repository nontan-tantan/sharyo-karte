# 車両カルテ（SHARYO KARTE）

業務車両を多数保有・リースする企業向けの、社用車管理アプリです。
車両IDを基点に、基本情報・所有／リース・保険・変更履歴を1台ごとの「カルテ」としてまとめ、
保険や車検の期限切れ、「売却済なのに保険が有効」といった登録内容の矛盾に気づけるようにします。

未来クライム4期（IT人材育成講座）の制作課題として開発しています。

## すぐに試す

**https://nontan-tantan.github.io/sharyo-karte/**

1. 上のURLをブラウザ（Chrome / Edge / Safari）で開く。パソコン・スマートフォンのどちらでも使えます
2. 最初は車両が0台なので、ダッシュボード下部の「サンプルデータ（17台）を追加」を押す
3. ダッシュボードの「要確認」や期限の近い車両を選んで、車両のカルテを見てみる

- 入力したデータは、開いた人のブラウザの中だけに保存されます（サーバーには送られず、ほかの人には見えません）
- 登場する会社名・保険会社名・人名・ナンバーはすべて架空のものです

## 手元で動かす

インストールやサーバーは不要です。

1. このリポジトリをダウンロード（またはクローン）する
2. `index.html` をブラウザで開く

## 主な機能

| 機能 | 内容 |
|---|---|
| ダッシュボード | 保有台数・稼働状況のサマリ、保険期限／車検期限が30日以内または超過している車両、要確認の車両を一覧表示 |
| 車両一覧 | 部署・用途・稼働状態・所有／リースでの絞り込み、フリーワード検索（統合で欠番になった旧車両IDでも検索可） |
| 車両詳細（カルテ） | 基本情報／所有・リース／保険／変更履歴の4タブ。売却・廃車の情報（相手先・日付・金額・理由）も記録 |
| 登録・編集 | 所有／リース、保険の有無、売却・廃車に応じて入力欄を出し分け。入力内容は自動で下書き保存 |
| 整合性チェック | 売却済・廃車なのに保険が有効／同じナンバーの重複登録を検知し、一覧・詳細・ダッシュボードで警告。その日に初めて開いたときはアラートでまとめて通知 |
| 重複登録の統合 | 残す車両を選び、異なる項目を見比べたうえで1台に統合（変更履歴は引き継ぎ） |
| 変更履歴 | 保存のたびに、変わった項目を「〇〇を「A」から「B」に変更」の形で日時・操作者名とともに自動記録 |
| CSVで一括取込 | ひな形をダウンロードし、今の台帳から貼り付けたCSVをまとめて登録（Excelで保存したShift_JISのCSVも可）。取り込む前に、件数とエラーのある行を理由つきで確認できる |
| 登録の取り消し | 間違えて登録した車両は削除せず取り消す（理由・操作者を記録し、あとから元に戻せる） |
| 車両IDの採番 | 全社通しの連番（例：V-001）を保存時に自動で採番（手で入力はしない）。登録したあとは部署異動があっても変えない。号車番号など今までの番号は「これまでの管理番号」に残せる |

## 設計上の主な判断

- **ログイン機能は作らない**：保存時に操作者の部署・名前を入力し、変更履歴に残す軽量な方式にしています
- **要確認でも保存はできる**：売却直後はすぐに保険を解約できないなど、現実には矛盾した状態が一時的に生じるため、保存は止めずに警告を出し続けます
- **重複はナンバーで判定**：車台番号の方が確実ですが、入力・管理の負担を考えてナンバー（表記ゆれを吸収して比較）を採用しました
- **一度使った車両IDは再利用しない**：過去の書類や記録と照合できるよう、売却・廃車・削除・統合のあとも番号を欠番として残します

## 技術構成

- HTML / CSS / JavaScript（フレームワーク・ライブラリなし）
- データ保存：ブラウザの localStorage（将来、複数部署で共有する段階では Firebase 等への移行を想定）
